# The toast fix — deploys must announce themselves (2026-07-17)

Presentation layer only. Base `3ba0125` (B4, live). The "A new version is ready" toast
shipped in B2b and has never fired across two deploys. This session makes it reachable.

## The finding, restated

The toast was not broken. It was **unreachable**, in two layers, and both had to be
true for it to stay silent:

1. **The served worker's bytes never changed.** `public/sw.js` carried a hardcoded
   `SW_VERSION = 'fox-s9-v1'` and was a static file, so every deploy served the same
   bytes. A browser decides "there is a new worker" by comparing the fetched `sw.js`
   byte-for-byte against the installed one; identical bytes mean *no update exists*, so
   `updatefound` and `controllerchange` — the only two events the toast can listen for
   — could never fire. No amount of correct decision logic downstream could help.
2. **Nothing ever asked the browser to look.** `ServiceWorkerRegister` never called
   `reg.update()`, and Next's client-side routing never triggers the browser's own
   check. An idle tab therefore waited on the browser's ~24-hour update check.

The B2b unit tests passed the whole time because they tested the *decision rules*
(`updateReadyNow`, `installedBehindController`, `controllerChangeMeansUpdate`), which
were correct then and are unchanged now. The rules were being asked a question that the
browser never posed. **The lesson, and it is the ledger line: unit tests proved the
decision logic while the production triggers were unreachable. A feature of this class
is only proven by a live deploy.**

## Task 1 — a per-deploy identity for the worker

- `git mv public/sw.js worker/sw.js`. It is a **template** now, not a served asset, and
  its version line is `const SW_VERSION = '__SW_VERSION__';`. It stays a real `.js`
  file — the caching posture is the product, and it should remain lintable, diffable,
  and highlightable rather than a string inside a `.ts` module.
- **NEW `lib/sw-source.ts`** reads the template once at module load and exports
  `swBody(version)`, which stamps the version into the **declaration**. It **throws** if
  that declaration is gone, if the version is empty, or if the version is not a bare
  identifier — under the build-time route a throw fails the build loudly, which is
  exactly the silent regression (a hardcoded version) this module exists to prevent.
- **NEW `app/sw.js/route.ts`** — `dynamic = 'force-static'`, serving
  `swBody(deployVersion())` as `text/javascript` with
  `cache-control: public, max-age=0, must-revalidate`. The path stays `/sw.js` at root,
  so the worker keeps root scope and every already-registered browser picks up the new
  bytes at its next check.
- **Identity:** `VERCEL_GIT_COMMIT_SHA` (platform-provided, no new env var), truncated
  to 12; falling back to `BUILD_TIME`, which `next.config.js` already bakes on every
  build; then a stable `dev` literal so a local dev server does not churn. Redeploying
  the *same commit* deliberately yields the same version — identical code is not a new
  version and the toast should stay quiet.
- **`STATIC_CACHE` already rides `SW_VERSION`** (`'fox-static-' + SW_VERSION`) so it
  rotates per deploy, and **the activate handler already deleted every cache that is not
  the current one** — the brief's "if it doesn't, add that" was already satisfied. No
  cache leak, verified live (below).

## Task 2 — asking the browser to check

`lib/sw-update.ts` gains `UPDATE_CHECK_INTERVAL_MS` (ten minutes) and
`scheduleUpdateChecks(check, host)`. The host (timers, the visibility listener, the
visibility read) is **injected**, so the triggers unit-test in node — this repo has no
jsdom, and that constraint is why the logic is pure rather than buried in the component.
`ServiceWorkerRegister` now calls `reg.update()` once after registration settles, then
on the interval, and whenever the tab becomes visible; teardown clears both. The
first-install guard and the decision rules are untouched, and **nothing auto-reloads**:
a check only *asks*; the rules still decide; the human still presses Refresh.

### Confirmed in production (deploy `e6d7aa6`, 2026-07-17)

`https://foxmortgage.ca/sw.js` and `https://www.foxmortgage.ca/sw.js` both return **200**,
`text/javascript; charset=utf-8`, `public, max-age=0, must-revalidate`, and
`const SW_VERSION = 'sha-e6d7aa614a1d';` — the first twelve characters of this deploy's
commit. So on the real domain: the served worker now carries the deploy's identity, the

That is layer 1 proven in production. Layer 2 (an idle tab noticing) still needs the next
deploy, because the tabs open right now are running the pre-fix component that never asks.

**The real acceptance cannot happen in this session and this report does not claim it.**
It is the **next deploy after this one**: an open, untouched portal tab should show the

## The adversarial review, and what it changed

Given the session's whole lesson, the change was reviewed by five independent lenses
(worker lifecycle, Next/Vercel build semantics, the caching posture, test vacuity,
guardrails), each finding then put to three refuters told to kill it. Three findings
survived; eight were killed. Five things changed as a result — two of them were fixes
to *my own guard*, which is exactly the failure this session is about:

1. **My placeholder guard was defeated by my own prose.** `worker/sw.js` names
   `__SW_VERSION__` in its header comment, and `swBody` asked "does the source contain
   the placeholder *anywhere*". So a future hardcoded `SW_VERSION` would have been waved
   straight through on the strength of a comment — the exact regression the guard exists
   to catch, silently reintroducing today's bug. The guard now matches the **declaration**
   (`const SW_VERSION = '__SW_VERSION__';`) and rewrites only that, leaving the prose
   intact and accurate. (The review "killed" this as a future-refactor risk; I disagree —
   a guard that a comment can satisfy is not a guard.)
2. **Nothing tested the route** — the one place the stamp reaches a browser. Gutting
   `GET` to serve the template unstamped kept all 647 tests green and restored the
   original bug exactly. There is now a test that imports the route. Same reasoning as
   above: this is the precise shape of the failure being fixed, so leaving it open was
   not defensible.
3. **A security assertion a comment could pass.** `tests/pwa.test.ts` proved the
   `isCacheable` guard is "invoked, not merely declared" by counting occurrences across
   the whole file — and the header comment discusses `isCacheable(url)` by name, so the
   prose alone satisfied it. The count now runs on code with comments stripped.
   (Pre-existing, inherited, fixed here.)
4. **Two tests were reading my shell, not the code.** JS default parameters fire on an
   explicitly passed `undefined`, so `deployVersion(undefined, …)` silently re-read
   ambient `process.env`. The refuter reproduced it: with `VERCEL_GIT_COMMIT_SHA` set,
   two tests failed. They now pass explicit empty strings. Verified fixed by re-running
   with that variable exported.
5. **A false comment.** I wrote that `next.config`'s `env` inlines both identity reads.
   It does not: a refuter proved from the compiled bundle that `BUILD_TIME` is inlined
   to a literal while `VERCEL_GIT_COMMIT_SHA` survives as a real `process.env` read that
   resolves *only because the route is `force-static`*. The comment now says so — the
   distinction is load-bearing for anyone editing this file.

**Also added, unprompted by any finding:** `swBody` now rejects a version that is not a
bare identifier. It is stamped into a single-quoted JS string literal, and while
`deployVersion` only ever yields hex or digits, `swBody` is exported. Closing the
injection shape costs one line.

## The known gap, recorded rather than fixed

**A hard-reloaded tab will miss one deploy.** Confirmed by all three refuters, including
a repro against the real rules. A hard reload (Cmd+Shift+R, or DevTools "Bypass for
network") loads the page with the worker bypassed, so the document is **uncontrolled**
even though a worker is active. All three toast paths gate on "this page has a
controller" as a proxy for "a worker was already installed", and that proxy is unsound
in exactly this case: the tab is misread as a first install and stays silent through the
next deploy. Every mechanical half of this fix works there — the triggers fire, the new
worker installs and activates — and the decision layer then discards the signal.

It is bounded: the failure is **silence, not a false toast**; it is **self-healing**
(once `clients.claim()` gives the tab a controller, the following deploy toasts
normally); and it needs a deliberate hard reload. But it lands on whoever hard-reloads,
which is usually the person shipping.

**Not fixed here, deliberately:** the brief scoped this session to "keep the existing
toast wiring untouched and add the missing triggers", and the decision rules are
pre-existing and unchanged. The fix is to compare worker **identity**
(`registration.active` at watch time vs the new controller) instead of mere presence,
which is correct in both directions and stays pure. Recorded as a known gap in
`lib/sw-update.ts` — where the docstring previously asserted the false premise outright
("no controller = the very first install") and now does not — and handed to B5.

## Findings from the build, not assumed

- **`STATIC_CACHE` already rotated and the activate handler already deleted every
  non-current cache.** The brief said to add old-cache cleanup "if it doesn't" — it
  already did, and the live run confirmed exactly one cache survives a version change.
  Nothing to add.
- **`/sw.js` needs no `publicRoutes` entry.** Clerk's middleware matcher excludes any
  path with a file extension, so it never sees `/sw.js`. Verified against the matcher
  and confirmed by the review.
- **`self.skipWaiting()` is load-bearing for the Refresh button.** With it, the new
  worker activates immediately, so Refresh lands on new code and `waiting` is rarely
  the path that fires (the `updatefound → installed` path is). Removing it would make
  Refresh reload into the *old* worker and the toast would reappear. Left alone.
