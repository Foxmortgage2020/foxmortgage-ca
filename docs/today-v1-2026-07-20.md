# Today v1 — the morning operating page

Date: 2026-07-20. Repo: foxmortgage-ca. Base: `main` tip `17f0bc3`. Presentation +
one pure model; NO writes anywhere, no Zoho reads added, no new fetchers, no migration.

Today stops being an exception-first dashboard-with-a-pile-of-cards and becomes the
page Michael works out of every morning. It answers three questions in order: what
needs me, what is moving, what is at risk. Each story is told once.

## Findings first

Inventoried the old Today (`app/portal/admin/page.tsx`) before touching it. What it read
from, and where the brief needed a loud deviation:

1. **The Zoho task read already existed.** `getTasksDue()` → `OpenTask[]` (`lib/zoho-admin.ts`)
   runs `GET /Tasks/search?criteria=(Due_Date:less_equal:today)`, reads only
   `Subject,Due_Date,Priority,Status`, drops `Completed` client-side, and self-labels each
   row `overdue` (due strictly before today). It returns due-today **and** overdue in one
   list; there is no separate overdue-only read. **DEVIATION (load-bearing):** the read
   carries **no deal reference** — no `What_Id`, no `$se_module`. So the brief's "deal link
   when a BRXM number is present" is met by parsing a file ref out of the task **subject**
   (`lib/today.ts parseDealRef`) and matching it to a workbench deal (`wbByFileRef`). No new
   Zoho read, no Zoho field added. A subject with no matchable ref simply shows no link.
2. **DEVIATION — the "sitting in Waiting-on-you" task-priority arm is not derivable.** A task
   carries no queue linkage, so a task cannot be known to be "in Waiting-on-you." The
   implemented urgency arm is the derivable one: a task referencing a deal **closing within
   30 days** sorts first (that deal's clock is the practice's clock), then earliest due.
3. **The duplicate pipeline table.** Two pipeline tables lived on Today: the compact
   per-file table (`pipeline.activeDeals` grouped by phase) and a separate "Pipeline by
   stage" census (`pipeline.ordered` + `pipeline.other`). The census is **deleted**; its
   stale-files groom line moves into The year.
4. **The 7-day closings block** read `computeClosings(deals, CLOSINGS_STRIP_DAYS=7)`. Widened
   to 30 (`CLOSINGS_BLOCK_DAYS=30`).
5. **The alert stack consolidates, it does not shrink.** The old tall pile of a dozen amber
   `AttentionCard`s becomes ONE danger-tinted exceptions block that ABSORBS (each story once,
   not dropped): the imminent-closing-with-overdue top line, overdue conditions, conditions
   due soon, the flags summary, funded deals with no maturity date, credential renewals, and a
   stalled sync. Signals that moved to their proper band instead: the act-now monitoring
   opportunities go to The year's leak line (with the count and a Beyond funding link); the
   renewal action/lapsed windows go to the leak line; closings-needing-attention is the
   Closings band's readiness chip. Nothing important is silently lost.
6. **DECISION — checkboxes omitted from the Tasks card.** A disabled checkbox on every row is
   dead affordance that promises a write build that is out of scope, and it crowds a 5-row
   card. The card instead carries a "Catch-up sweep" link to the overdue backlog and a
   "N more in Zoho" link, so the backlog never crowds today. No writes to Zoho.
7. **DECISION — the Rates summary card is dropped from Today.** It is reference data, not a
   morning "needs me / moving / at risk" signal, and pending sheet reviews already surface in
   the Waiting-on-you strip. The full rates browser lives on Lenders.
8. **DEVIATION — renewal nurture carries only three of the five brief states.** The portal
   read model (`getRenewalSequenceStates`) exposes entered / drafts-minted / sent. `replied`
   and `no reply after the full sequence` need a workbench field that does not exist yet
   (there is no reply signal anywhere in the portal). The band renders the three honest
   states and says reply tracking arrives with the send build. While the send build is dark
   every `sentCount` is 0, so the band reads "Sends not yet live."
9. **DECISION — the at-risk block spans permissions.** The brief names overdue conditions, the
   flags summary, and stalled sync; the block also carries credential renewals (compliance.view),
   due-soon conditions, and missing-maturity funded deals (renewals.view) — each an at-risk
   signal from the old rail, each gated so it only appears for a role that can act on it, and
   the stalled-sync line is gated on status.view so its Status link is never a dead link. A
   closing whose condition read failed reads "condition state unavailable" (neutral), never a
   false green.

## What shipped

### The relative-date helper (new, portal-wide) — `lib/dates.ts`

`daysUntilYMD(targetYMD, todayYMD)` (whole days, negative in the past, UTC-midnight) and
`relativeDay(targetYMD, todayYMD, soonDays=7)` → `{ days, tone, label, dueLabel }`. `tone` is
`danger | caution | neutral | success` and **never** maps to the decision (lime) token. `label`
is neutral ("today", "in 3 days", "5 days ago"); `dueLabel` frames a deadline ("due today",
"5 days overdue"). This replaces the scattered per-surface day-diff math (compliance's
`daysUntil`, the deals-surface inline phrasing); those stay in place, new surfaces use this.
Unit-tested in `tests/dates.test.ts`.

### The pure model — `lib/today.ts` (unit-tested, `tests/today.test.ts`)

- `parseDealRef` — a file ref (`BRXM-F…` / `IFMS-F…` / `FOX-1004` / `DEMO-F0001`) out of any text.
- `prioritizeTasks` — closing-within-30 first, then earliest due; resolves the deal-room link
  and overdue/overflow counts for the footer.
- `closingReadiness` / `buildClosingRows` — per-closing readiness from the file's conditions
  (danger overdue / warning open / success clear / neutral "not linked to the workbench yet").
- `renewalNurtureBuckets` — entered / drafts-minted / sent + `sendsLive`.
- `buildExceptions` — the one at-risk block: an imminent closing with overdue conditions leads
  (the loudest line), then overdue-conditions, the flags summary, credentials, and stalled
  sync; block tone is the max severity; null when nothing is at risk.

### The bands — `components/admin/today/*` (none use lime/decision)

`ui.tsx` (Band wrapper + `RelativeChip`), `YourDay` (calendar teaching state + live tasks),
`Exceptions` (the at-risk block + the quiet healthy-sync line), `RenewalNurture`, `WhatsMoving`
(the single lifecycle table), `Closings`, `TheYear`. The three decision cards stay inline in
`page.tsx` — the decision token is enumerated to that file for exactly that role.

### The page — `app/portal/admin/page.tsx`

Band order: **a.** Fraunces greeting + one pulse line (date · funded YTD with file count ·
pace delta tinted by sign · open file count). **b.** Your day (calendar teaching state beside
the live tasks). **c.** Waiting on you — the navy Desk strip, the three decision cards (lime
top border), the one exceptions block, and a quiet green healthy-sync line at the bottom when
nothing is stalled. **d.** Renewal nurture (slim, renewals.view). **e.** What's moving (the
single lifecycle table, every active file by phase, closing-date order, plain-words next step,
relative close chip, amount, stage, deal-room link). **f.** Closings in 30 days (readiness
chips). **g.** The year (four tiles, the pacing bar, the leak line → Beyond funding, the groom
line). Every count still derives from its owning page's loader (the Desk pattern) — this page
re-derives nothing, it reshapes.

## Cross-cutting patterns (added to CLAUDE.md standing rules)

- **Relative dates with urgency tinting** use `lib/dates.ts relativeDay` (never the decision
  token for date urgency).
- **Every file ref rendered on Today links to its deal room** (`parseDealRef` + the workbench
  join).
- **Teaching empty states**: an empty band explains what it is for and the first action in one
  sentence, house copy rules (no em dashes / no exclamation points / no semicolons / Grade 6 /
  sentence case / verbs on buttons). The calendar card is the model until the Microsoft build
  lands — one sentence and a "Connect your Microsoft calendar" action, no fake events.

## Adversarial review

Four skeptics (correctness / permission-reconciliation / design-lime-copy / honesty), each
trying to refute that the build is correct and complete. 10 findings raised, 9 fixed + regression
tests, 1 accepted with rationale:

- **Missing-maturity funded deals were dropped** (the old rail's amber alarm). Restored as a
  renewals-gated line in the one exceptions block.
- **Due-soon conditions were dropped** (the early warning before a condition flips overdue).
  Restored as a caution line in the exceptions block.
- **The stalled-sync line was a dead link for the agent role** (links to Status, which agents
  cannot reach). The sync input is now gated on `status.view`, mirroring the credentials gate.
- **A failed condition read painted a bridged closing a false green** ("0 open conditions").
  `buildClosingRows`/`closingReadiness` now take a `condsAvailable` signal; a failed read reads
  "condition state unavailable" (neutral).
- **Credential exceptions were suppressed when the workbench was unconfigured** (the
  not-connected notice replaced the whole block). The notices are now additive and the at-risk
  block always renders (credentials come from FOXCA, independent of the workbench).
- **The act-now monitoring count was lost** (only the dollar survived, revenue-gated). The leak
  line now reads "$X to call across N files".
- **The "Connect your Microsoft calendar" button was an inert dead control.** Marked disabled
  and muted with a "Coming soon" hint, so it teaches without implying a working action.
- **Docs numbering nit** — fixed.
- **Accepted (low, loud/safe):** the closings overdue count (from `getConditionsDue`, no
  gate_status filter) can include a pending-but-overdue commitment condition the approved
  open-count excludes. The direction is never a false green, and a pending overdue condition on
  a file about to close is genuinely worth a look; matches the prior page's behavior.
