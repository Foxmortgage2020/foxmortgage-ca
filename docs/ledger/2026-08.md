### 2026-08-01 — A2: the Tasks page, the Zoho exit's tasks lane

The block spec is `../../fox-underwriting/docs/zoho-exit/blocks/A2-portal-today-page.md`;
the endpoint contract is that repo's `REPORTS/A1.md` and `docs/gates-api.md`
("The native task system"). This repo consumed both as published contracts and
changed nothing in fox-underwriting (guardrail 8, one direction only).

- **Authority keys mirrored, not invented.** `tasks.view`
  (admin/ops/underwriting-reviewer/agent) and `tasks.manage` (admin) added to
  `config/authority.ts`, matching that repo's values verified against its
  `src/gates/tasks.test.ts` rather than assumed. Deliberately SEPARATE from the
  pre-existing `tasks.complete`, which is the LEGACY Zoho card's key and writes
  to Zoho; the two new keys never touch Zoho. One key covering both would make
  `tasks.complete`'s "(writes to Zoho)" label a lie on half its calls.
- **`/portal/admin/tasks`, nav label "Tasks", in the `today` group** beside
  Today. Not named "Today" because that label is taken by `/portal/admin`, and
  two things called Today is how a person ends up on the wrong one.
- **Counts are the server's, always.** Every bucket heading reads
  `counts[bucket]`, never `rows.length`. A1 shipped and fixed the opposite
  defect (counts taken after the 200-row cap, so 276 overdue reported 200);
  `tests/today-tasks.test.ts` pins the distinction with those exact numbers.
- **Paging past the cap, without touching fox-underwriting.** The endpoint caps
  each bucket at 200 and accepts no paging params, so the remaining 76 overdue
  rows are unreachable from it. `tasks` is granted to `portal_readonly`
  (migration 0057), so `getOverdueTasksPage` in `lib/underwriting.ts` reads the
  rest through the existing GET-only wrapper, behind
  `/api/portal/admin/tasks/overdue`. **`as_of` is passed back VERBATIM from the
  endpoint's own response** — the browser never recomputes "today" and neither
  does the route; a missing or malformed `asOf` is refused (422), never
  defaulted, because a defaulted date is a silently different filter. "Show the
  remaining N" REPLACES the overdue list rather than appending: the endpoint
  orders by `due_date` alone, so ties break arbitrarily and appending offset-200
  onto that first page would duplicate some rows and drop others.
- **Bulk triage over the existing endpoints.** Multi-select plus bulk complete
  and bulk dismiss, calling the per-task gate endpoints IN SEQUENCE. No bulk
  endpoint was invented, so every row still lands its own audit entry carrying
  the real human's identity — which is the entire point of guardrail 19.
  Progress counts through; `summarizeBulk`/`bulkSummaryLine` report partial
  failure honestly and count 409 as already-done rather than as an error.
- **Single-tap complete on a row is a deliberate departure** from the approvals
  desk's two-tap confirm, recorded here rather than left to be discovered: this
  is a task list, not a decision queue, and two taps across 276 rows is what
  makes a page get abandoned. Dismiss carries its own friction (a typed reason)
  and the bulk verbs confirm with their count first.
- **Five routes.** `GET /api/portal/admin/tasks/today` and
  `/api/portal/admin/tasks/overdue` behind `tasks.view`; `create`,
  `[taskId]/complete`, `[taskId]/defer`, `[taskId]/dismiss` under
  `/api/portal/admin/gates/tasks/` behind `tasks.manage`. The Zoho-legacy
  `/api/portal/admin/tasks/[id]/status` is untouched and coexists.
- **Demo mode** gets its own fixture (`demoTasksToday`), served at the fetcher
  boundary before any network call — task titles carry client names in the real
  store. The fixture is deliberately truncated (3 rows against a count of 34) so
  a walkthrough exercises the same paging affordance the live page shows.

**Verified live (dev Clerk instance, ephemeral TEST admin, deleted after):**
four buckets with true counts, the "showing 3 of 34" banner and its
"Show the remaining 31" control, action controls and the bulk bar at 375px and
1280px with zero horizontal overflow, the paged-read guards (422 on a missing,
malformed, or injected `asOf`), and the non-admin posture: an `ops` session
reads the page, renders ZERO action controls, and is refused 403 by the SERVER
on both complete and create. Suite 1241 tests (26 new), typecheck clean, build
green.

`gates` template: none at all (`GET /v1/jwt_templates` returns `[]`). So no
gates token can be minted there, and the four writes cannot be exercised from
local dev against the production workbench. The page degrades honestly to
"Your session did not produce a token" rather than crashing or showing an empty
list. **A1's one unproven item therefore remains open at the end of this
session** — see the outstanding note below. Fabricating an identity to close it
is what A1 refused and what guardrail 19 exists to prevent.

**FINDING — `npm run queue:status` in fox-underwriting cannot see this PR.**
`listPullRequests` runs `gh pr list` with `cwd: REPO_ROOT` and no `--repo`
flag, so it only ever sees fox-underwriting pull requests. A2's PR lives here,
so nothing in that repo's derived queue state will reflect it and A2 stays
`ready` there. A2 is a checkpoint so the run ends anyway this time, but a future
cross-repo block would hit the same duplicate-rebuild bug H1b was built to kill.
